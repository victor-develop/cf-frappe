# ReturnsOS Independent Architecture Review

## Scope

An independent software architect agent reviewed the complete ReturnsOS implementation after browser verification and successive remediation rounds. The review covered:

- named multi-workflow and composite-command boundaries;
- durable, idempotent, retryable Automation Runs;
- Guest, persona, field, and demo-operator authorization;
- the request-identity-scoped public intake boundary;
- the standalone product frontend and its delegation to framework authorization and command boundaries;
- concurrent Order claiming and asynchronous projection behavior;
- deterministic seed and repeat-run guidance;
- tests, enforced branch coverage, browser evidence, and operating documentation.

## Review Rounds

The review was not treated as a one-shot sign-off:

1. The complete application and framework integration review produced the authorization, concurrency, request-boundary, body-limit, and generated-ID findings listed below. Each finding was remediated and covered by regression tests.
2. A focused Naming Engine review then challenged atomicity, retry behavior, metadata races, generated-field immutability, exclusion safety, and pattern invariants. Its final Medium finding showed that an escaped hyphen in a safe-regex character class, such as `[a\-z]`, was incorrectly interpreted as a range.
3. The parser was changed to preserve escape metadata for character-class entries and to create a range only for an unescaped middle hyphen. Positive and negated regression cases were added.
4. The independent architect reproduced typecheck and all 37 focused safe-regex tests, then reported zero High, Medium, or Low findings and returned `PASS`.

## Findings Resolved During Review

1. Guest read and metadata permissions were removed from `Customer` and `Order`. Public intake now uses bounded validation and a request-scoped internal role without exposing master-data APIs.
2. `/demo/automation-runs` now requires Demo Administrator and is absent from non-admin demo homes.
3. `Return Request.order` now uses cf-frappe's event-sourced unique-value reservation. The reservation commits atomically with Return creation, so two concurrent requests cannot both claim one Order before `has_open_return` is projected.
4. `PublicReturnIntakeBoundary` owns verification, normalized forwarding, generic failure mapping, WeakSet request identity, and `finally` cleanup. Spoofed headers and cookies do not select the internal actor.
5. The public-intake security module is included in the enforced coverage gate. Repeat runs use the separate unused `ORD-1008` fixture.
6. Standalone action forms now enforce the 8 KB limit against bytes actually streamed from the request, even when `Content-Length` is absent. An oversized valid command returns `413` before dispatch and leaves the document snapshot unchanged.
7. `Return Request.return_id` is now generated by the framework Naming Engine. Caller values are rejected across JSON and both HTML aliases; the document name, generated field, yearly named counter, unique reservations, and create event share one atomic commit.
8. Safe-regex character classes preserve escaped hyphens as literals, including negated classes, instead of widening them into ranges.
